▸ 2026-09-27T18:27:30Z [claude]
Root cause: ~/.config/niri/cfg/display.kdl had the output block disabled by KDL's slashdash operator. Line 6 read '/- output "DP-1" {' -- a leading /- comments out the ENTIRE following node, so niri never saw it and fell back to the panel's preferred mode (3840x2160@59.997) at scale 1. The file's own line 3 warned about this ('You will have to remove "/-" and edit it before it takes effect'); it also still had the shipped template values, mode "2560x1440@359.979" and scale 1, which match no mode this display offers.

Fixed: removed the /-, set mode "5120x2160@74.979" and scale 1.5. 74.979 is the highest refresh the Lenovo P40w-20 offers at 5120x2160 and the string must match 'niri msg outputs' exactly. VRR is reported unsupported on this panel, so no variable-refresh-rate key.

Verified: 'niri validate' passes; niri hot-reloaded at 14:24:44 and reports 'Current mode: 5120x2160 @ 74.979 Hz / Scale: 1.5 / Logical size: 3413x1440'. Real confirmation is the reboot - verify: command set for that.

NOTE - ~/.config/niri is NOT chezmoi-managed (only .config/{fish,git,kitty,nvim,zed} are), so this fix is untracked and would be lost on a rebuild. That is the deeper 'doesn't stick'.

Separately: the greeter has its own scale, independent of niri. noctalia-greeter-compositor supports an 'output_scales' setting (format NAME:1.25, per its error strings) and its state dir is /var/lib/noctalia-greeter (greeter.toml, 0750 greeter:greeter - not readable as joel). So the login screen's scale is a different knob if it looks wrong on reboot.
